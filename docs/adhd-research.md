# ADHD 友好产品与相关研究调研

**结论先行**

- 市面产品靠五种机制降摩擦：视觉锚点、任务拆解、时间外置、即时反馈、陪伴问责
- adhd-md 已覆盖前四种中能落进纯 Markdown 的部分
- 本次新增 A7/A8/N7 三条规则，H4 从 `deep` 提到 `standard`
- 明确不采纳词首加粗与 emoji 锚点，理由在证据库

## 一、市场扫描

### 1. 阅读层：直接改造文字

| 产品 | 做法 | 机制 | 证据状况 |
|---|---|---|---|
| [Bionic Reading](https://bionic-reading.com/) | 加粗每个词的前半段，声称制造「注视点」帮助眼睛自动补全 | 视觉锚点 | 三项独立研究未见阅读速度或眼动收益（Snell 2024；Beelders 2025；Možina 等 2025），详情见 2.2 |
| [BeeLine Reader](https://www.beelinereader.com/) | 文字行尾到下一行行首用颜色渐变引导视线 | 视觉锚点 | 有商业宣称与用户案例，未查到同等强度的独立对照研究 |
| [Readwise Reader](https://readwise.io/read) | 去杂讯阅读视图、高亮、朗读、专注模式 | 降噪 + 多模态 | 产品机制成熟，未做 ADHD 特异性宣称 |
| [Speechify](https://speechify.com/) | 文字转语音、语速调节、边听边看 | 多模态补偿 | 听读结合是通用辅助技术做法，ADHD 场景的用户证言多、对照研究少 |
| [Microsoft Immersive Reader](https://learn.microsoft.com/en-us/immersive-reader/) | 行聚焦、字号字距、音节拆分、朗读 | 降噪 + 多模态 | 属于主流无障碍功能，设计依据来自通用阅读障碍研究 |
| 浏览器阅读模式（Safari Reader 等） | 剥掉广告、侧栏、排版噪音 | 降噪 | 直接对应「噪音归零」原则，无需专门研究也能成立 |

结论：这一层最值得借鉴的是**降噪**和**多模态**，不是词首加粗。

### 2. 任务拆解与启动层

| 产品 | 做法 | 机制 |
|---|---|---|
| [Goblin Tools](https://goblin.tools/)（Magic ToDo / Compiler / Estimator） | 把大任务自动拆成一步一个动作的小步骤，给每步估时长 | 任务拆解 + 时间外置 |
| [Inflow](https://www.getinflow.io/)（Quinn 对话助手） | 用对话把「打扫厨房」拆成可执行步骤 | 任务拆解 + 即时反馈 |
| [Tiimo](https://www.tiimoapp.com/) | AI 规划助手把脑内清单变成可排序、可执行的一天 | 任务拆解 + 优先级外置 |

共同模式：**不让读者/用户自己从「大目标」推导「下一步」**。拆解产物总是单动作、带顺序、带时间。

### 3. 时间与计划层

| 产品 | 做法 | 机制 |
|---|---|---|
| [Llama Life](https://llamalife.co/) | 每次只显示一个任务，每个任务倒计时（timeboxing），显示总清单时长与预计完成时间 | 时间外置 + 单一焦点 |
| [Tiimo](https://www.tiimoapp.com/) | 视觉日程、专注计时器、时间不可感知（time agnosia）是官方文案关键词 | 时间外置 |
| [Structured](https://structured.app/) | 一天铺成可视化时间轴，大任务拆子任务，漏掉的任务自动改期 | 时间外置 + 结构外置 |

共同模式：**把「还剩多少时间」从脑子里搬到界面上**。这与 ADHD 时间感知缺陷的研究直接对上（见 2.1）。

### 4. 陪伴与问责层

| 产品 | 做法 | 机制 |
|---|---|---|
| [Focusmate](https://www.focusmate.com/) | 配对陌生人开摄像头一起工作（virtual body doubling） | 社交问责 |
| [FLOWN](https://flown.com/) | 在线集体专注时段，官方把 ADHD 列为目标人群 | 社交问责 |

身体双倍（body doubling）有 HCI 实证研究（Eagle 等 2023），但它是**实时人际机制，落不进静态 Markdown**。adhd-md 能做的是把「我做到哪了」外置成复选框与进度标注。

### 5. 治疗与训练层

| 产品 | 做法 | 证据状况 |
|---|---|---|
| [EndeavorRx / EndeavorOTC](https://www.endeavorotc.com/) | 处方游戏训练注意力，FDA 首个授权的 ADHD 数字疗法 | 关键试验有效应但小；后续综述认为数字干预证据在积累，效力与适用人群仍需更多独立试验（PMID 40935381、42358407） |

### 6. 标准与学术框架

[W3C COGA《Making Content Usable》](https://www.w3.org/TR/coga-usable/) 是 W3C 认知无障碍工作组的官方指导文件，多条模式直接支持 adhd-md 的做法：

| COGA 模式 | 要求 | adhd-md 对应 |
|---|---|---|
| 4.4.5 Keep Text Succinct | 短段落、一段一主题、段落目的放在开头、短句、列表 | P1/P2/S5/W1 |
| 4.4.8 Summary of Long Documents | 长文档给摘要，关键词加粗 | H1/H2/T2 |
| 4.4.9 Separate Each Instruction | 每条指令单独成步，步骤不省略 | A7/A8/L3 |
| 4.2.4 Make Each Step Clear | 多步流程显示当前步、剩余步、关键选择 | N7（本次新增） |
| 4.5.10 Provide Feedback | 每步给完成反馈，减少「我做对了吗」的不确定 | A7（本次新增） |
| 4.3.5 Break Media into Chunks | 长内容切成有标签、可跳转的短块 | S3/P 组/N4 |

## 二、ADHD 相关研究

### 2.1 关键机制与数字

| 机制 | 证据 | 对文档意味着什么 |
|---|---|---|
| 工作记忆缺陷 | 儿童 ADHD 空间工作记忆 d=0.85–1.06，言语工作记忆 d=0.43–0.47（Martinussen 等 2005）；Barkley（1997）把工作记忆列为执行功能核心 | 要求「记住上文才能读懂下文」的结构都在制造失败：长句、长段、回扫、嵌套 |
| 时间感知缺陷 | 时间感知缺陷汇总效应量 g=0.688（824 个效应量，2024 荟萃）；表现为内部时钟偏快、短时估计变异性大（PMID 34923055） | 「大约要读多久」不是礼貌，是刚需 |
| 延迟厌恶与奖赏 | 双通道模型（Sonuga-Barke 2003）；多巴胺奖赏通路异常（Volkow 等 2009） | 远处奖励不驱动行动。需要即时反馈、小胜利、明确下一步 |
| 执行功能启动困难 | Barkley 1997 的统一理论；国际共识声明（Faraone 等 2021） | 能直接复制的命令、默认推荐、只做一件事的入口，都在降低启动成本 |
| 走神与理解 | 走神与阅读理解相关 r=−0.21（25 项研究荟萃，2023） | 文本越长越无聊，走神越致命；结论前置缩短「还没到重点」的时间窗 |
| 注意与阅读理解的直接关系 | ADHD 青少年的持续注意与阅读理解显著相关；行距和呈现媒介与注意水平存在交互（Stern & Shalev 2012） | 排版不是装饰。对注意差的人，文本呈现方式改变理解结果 |
| 认知负荷 | 认知负荷理论（Sweller 等 2019）；多媒体学习原则：signaling、segmenting、coherence（Mayer） | 引导、分段、去噪音都有独立理论依据，不只适用于 ADHD |
| 组块容量 | 短时记忆约为 4 个组块（Cowan 2001） | 要点列表 5 条以内、项目超 7 分组（L6） |

### 2.2 对产品调研的反向结论

**Bionic Reading 没有过关。** 三篇独立研究一致：

- Snell（2024）：100 段文字对照，Bionic 与普通字体阅读时间无显著差异
- Beelders（2025）：眼动仪显示注视点并不停在词首，低频词也不受益
- Možina 等（2025）：Bionic 阅读时间反而更长，且没有比普通排版更快

**词首加粗这种锚点无效，稀疏的语义锚点有效。** 标题、少量加粗的关键词、列表、引用块才是有效锚点 —— adhd-md 的 T2/T3/T5 已经这么做。

**app 市场重功能轻证据。** ADHD 移动 app 系统综述（Poetar 等 2020）与 MARS 质量评估（2025）结论一致：多数 app 质量中等，胜在功能，弱在参与设计。

声称与临床证据之间的缺口大。所以 adhd-md 不学产品话术，只学可检验的机制。

**别用「缺陷修复」框架做产品。** HCI 内部视角综述（Spiel 等 2022）与儿童 ADHD 技术综述（Stefanidi 等 2022、2023）指出：主流设计把 ADHD 当「需要压制的偏差」，很少让 ADHD 人群共建。

落到文档工具上就是：说「让文档更容易扫读」，不说「治好你的注意力」；把选择权留给读者，不替读者决定什么内容不重要。

## 三、应用到 adhd-md

### 3.1 机制 → 规则映射

| 机制 | 已覆盖（规则） | 本次补强 |
|---|---|---|
| 工作记忆有限 | P1/P4/S3/W1/W4/L1/L5 | — |
| 结论优先（降启动成本） | S5/H1/H2 | — |
| 任务拆解 + 每步可验证 | L3/A1/A4 | **A7 每步给预期输出或验证方法** |
| 一步一个动作 | L7/P2 | **A8 一步只做一个动作** |
| 时间外置 | H4/A2 | **H4 从 deep 提到 standard** |
| 走神后重新定位 | TOC/标题/序号 | **N7 多步流程标注进度** |
| 即时反馈 | 复选框、预期输出 | A7 |
| 降噪 | M 组/X 组/T 组 | — |
| 不采用视觉锚点伪科学 | X1/X5/T2 | 调研记录进证据库，防止以后「优化」回来 |

### 3.3 明确不采纳

| 做法 | 为什么不采纳 |
|---|---|
| Bionic Reading 式词首加粗 | 三项研究无收益，且与 T2 加粗密度、X5 过度加粗直接冲突 |
| BeeLine 式颜色渐变 | Markdown 无法承载颜色；改站点主题是另一个产品决策，不混进文档格式规则 |
| 文字转语音、游戏化训练 | 不是 Markdown 结构问题，属于宿主/阅读器能力，adhd-md 不越界 |
| emoji 当锚点 | X1 已有结论：屏幕阅读器逐字念、跨平台字形不稳、密度一高就失效 |
| 身体双倍/社交问责 | 实时人际机制，无法由静态文档提供 |

## 局限

- 未做系统综述：研究部分读的是摘要和部分全文，可能有漏检与发表偏倚。
- 产品调研依赖官网自述和商店元数据，没有逐家付费实测。
- ADHD 异质性很大：同一机制对不同亚型、不同年龄效果不同；adhd-md 给的是「降摩擦的默认值」，不替代个体化工具。
- 时间预估、进度标注等新规则是**从机制推导的工程判断**，目前没有专门的 RCT 证明「给文档加进度标注能提高 ADHD 读者完成率」。证据库按「机制证据 / 直接证据」分级标注。
