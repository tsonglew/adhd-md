# before / after 示例

四组对照。每组演示一种 scope × level 组合，以及**故意没做什么**。

`.before.md` 是真实风格的糟糕文档，`.after.md` 是改造结果。

## 四组分别教什么

| 组 | 类型 | scope / level | 脚本分 | 教什么 |
|---|---|---|---|---|
| 01 | 中文会议记录 | `both` / `deep` | 73.6 → 100 | 全量重构：待办前置、讨论过程折叠 |
| 02 | 中文 README | `format` / `standard` | 86.4 → 100 | **一个词都不改**也能大幅改善 |
| 03 | 英文运维手册 | `both` / `standard` | 68.5 → 100 | 步骤化 + 复选框 + 止血前置 |
| 04 | 英文 API 参考 | `format` / `light` | 81.8 → 88 | **克制**：参考文档不该大改 |

## 01 · 会议记录（deep + both）

收益最大的类型。原文是一坨叙述，待办埋在最后一段。

**做了**：待办提到最前并加复选框 · 决定 / 放弃 / 未定三分 · 放弃方案做成表格 · 一小时二十分钟的讨论过程折叠进 `<details>` · 长句拆短（句子负荷 30 → 100）

**没做**：讨论过程一个字没删。它折叠了，不是消失了 —— 半年后有人要考古「当时为什么否掉加机器」，答案还在。

## 02 · README（format only）

最值得细看的一组。**after 与 before 的正文词序列完全一致**，`verify --scope=format` 通过。

**做了**：性能结论那一段整块搬到开头（搬移，不改写）· 一坨拆成四段 · 四句配置说明转成列表（复用原句）· 裸标识符包成行内代码

**没做**：
- 没给配置列表加小标题。「配置」这两个字原文没有 —— 加了就是新写措辞，越界成 content。
- 没写 TL;DR。同理。

这就是 format 档的天花板：**结构可以大改，一个词都动不了。** 想要小标题和 TL;DR，得开 `content`。

## 03 · 运维手册（standard + both）

凌晨三点被叫起来的人在读，对可读性最苛刻。

**做了**：止血结论前置（两大常见原因 + 15 分钟升级线）· 三段排查各成一步，命令独立成块 · 升级信息与事后事项做成复选框 · 裸 URL 换成有意义的链接文本 · 消灭「As mentioned above」

**没做**：没把三步压成一个表格。表格里塞不进命令块，而半夜需要的是能直接复制的命令。

**这组第一版写砸了**：我把整句话加粗、每步一节，跑出来 X 扣分 −14（X2 碎片化 + X5 过度加粗）。修法是只加粗关键词、把说明合回步骤内。工具抓自己的狗粮抓得挺准。

## 04 · API 参考（light + format）

演示克制。参考文档的读者是来查一个条目的，重排会破坏跳读。

**做了**：H1 → H3 跳级修成 H2 · 代码块补 `js` 标签 · 去掉六处无意义加粗 · 标识符包成行内代码 · `**Parameters**` 后补空行

**没做**：
- 没把参数列表改成表格 —— `light` 档不动结构
- 没拆 `options.sanitize` 那个 45 词长句 —— 拆句是 content 操作
- 没写 TL;DR —— 同理

所以 04 的分数停在 **88，不是 100**。这不是缺陷，是 `format` + `light` 的正确结果。**分数不是越高越好，越高的分数可能意味着越大的越界。**

## 怎么重新验证

```bash
cd skill/references/examples
A=../../scripts/adhd_md.py
python3 $A report 02-zh-readme.before.md 02-zh-readme.after.md --scope=format
python3 $A verify 02-zh-readme.before.md 02-zh-readme.after.md --scope=format
```

四组同时验证（也已接进单测，`selftest` 会跑）：

```bash
python3 skill/scripts/adhd_md.py selftest
```

## 关于 before 的分数

四组 before 的脚本分在 68–86 之间，看着不算低 —— 但它们读起来都很糟。

原因：脚本分把 31 条需模型判断的规则按满分计入。「标题是不是话题式」「段落是不是一段讲三件事」「有没有明确下一步」这些扣分项脚本判不了。

**脚本分低说明一定有问题，脚本分高不说明没问题。**
