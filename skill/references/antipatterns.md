# 反模式：优化过头

原文难读，是一个问题。优化过头之后**难读且信息丢失**，是两个问题。

这个文件收录 adhd-md 最容易犯的八种错误。每条给出「原文 → 错误的改法 → 正确的改法」。X 组规则直接对应本文件，命中即扣分。

---

## X1 · emoji 汤

**默认零 emoji。** emoji 看着像视觉锚点，实际是噪音：屏幕阅读器会逐个念出来，同一符号在不同平台字形不同，而且一旦密度上来，锚点作用就归零。

```markdown
<!-- 错 -->
## 🚀 快速开始
先 📦 装依赖，然后 ⚡️ 跑起来，遇到 🐛 看 🔧 排查章节。

<!-- 对：用文字标签和引用块做锚点 -->
## 快速开始
先装依赖，再跑起来。出错看「排查」一节。

> **注意**：Node 18 以下不兼容。
```

需要视觉锚点时，用这些不带副作用的手段：`> **注意**`、`> **警告**`、表格、分割线、代码块。

表格里的 `✓ ✗ ✔ ✘` 和箭头 `→` 不算 emoji：字形单色稳定、语义唯一，扫读比文字更快。带变体选择符的彩色版本（`✅`）仍然算。

## X2 · 碎片化

把长文档切成一堆两行小节，读者失去主线，目录变成噪音。

```markdown
<!-- 错：四个标题，每节一行 -->
### 装依赖
npm install

### 改配置
编辑 config.json

### 起服务
npm start

### 验证
打开 localhost:3000

<!-- 对：一个标题 + 有序步骤 -->
## 跑起来（约 3 分钟）

1. 装依赖：`npm install`
2. 改配置：编辑 `config.json`
3. 起服务：`npm start`
4. 验证：打开 `localhost:3000`
```

判据：标题不得密于每 5 行 1 个；**纯正文**章节平均长度低于 40 字 / 25 词说明切得太碎。

含代码块或复选框列表的章节不计入这个平均 —— 运维手册每步一节、每节一条命令，是正确结构。

**分块和碎片化的区别**：分块是把一坨内容切成几个能独立读懂的单元；碎片化是把一个连续动作切断成互不相干的碎片。

## X3 · 要点糊

把句子砍成关键词，读者得自己补回语义。这是「列表化」最常见的翻车方式。

```markdown
<!-- 原文 -->
缓存默认是开启的，如果要关掉需要改配置并重启。性能瓶颈主要在序列化环节，
网络不是问题。另外 Node 18 以下的版本不兼容。

<!-- 错：砍成标签云 -->
- 缓存
- 性能
- 版本兼容

<!-- 对：每项自带完整判断 -->
- 缓存默认开启，关掉要改配置并重启
- 性能瓶颈在序列化，不在网络
- Node 18 以下不兼容
```

自检：把列表项单独拿出来读，能不能读懂？不能就是糊了。

## X4 · 删信息（硬失败）

唯一不可协商的红线。**adhd-md 只重排信息，不删信息。**

```markdown
<!-- 原文 -->
超时默认 30 秒。可以用 `--timeout` 改，单位是毫秒。
设成 0 表示不超时，但生产环境不建议这么用，因为连接泄漏时不会自动断开。

<!-- 错：以「精简」为名删掉了约束条件 -->
超时默认 30 秒，用 `--timeout` 改。

<!-- 对：结构变了，信息一条不少 -->
超时默认 30 秒，用 `--timeout` 改，单位毫秒。

设成 `0` 表示不超时。生产环境别这么用 —— 连接泄漏时不会自动断开。
```

篇幅太长时的正确做法是**折叠或移到附录**，不是删。

## X5 · 过度加粗

加粗的作用是让眼睛在扫读时有落点。落点超过一定密度，就等于没有落点。

```markdown
<!-- 错 -->
**超时**默认 **30 秒**，可以用 **`--timeout`** 参数**修改**，单位是**毫秒**。

<!-- 对 -->
超时默认 **30 秒**，用 `--timeout` 改，单位毫秒。
```

上限：≤8% 正文字符，单段 ≤2 处。超过 12% 直接扣分。

## X6 · 表格滥用

表格适合**同构、可对比**的数据。叙述性内容塞进表格会被列宽压成一团。

```markdown
<!-- 错：因果叙述硬做成表 -->
| 步骤 | 说明 |
|---|---|
| 第一步 | 因为配置文件在启动时只读一次，所以你必须先停掉服务，否则改了也不生效 |

<!-- 对：叙述就用叙述 -->
1. 停服务。配置文件只在启动时读一次，不停服改了不生效。
```

判据：单元格超过 15 字就该考虑不用表格。

## X7 · 折叠滥用

`<details>` 是给「不需要的人省视线」，不是给作者藏内容。

```markdown
<!-- 错：核心步骤被折叠，读者不点开就完不成任务 -->
<details><summary>安装步骤</summary>
1. npm install
2. npm start
</details>

<!-- 对：折偏离主路径的内容 -->
1. `npm install`
2. `npm start`

<details><summary>装不上？看这里</summary>
Windows 上如果报 node-gyp 错误，先装 build tools……
</details>
```

自检：读者要完成本文档的核心任务，需要展开它吗？需要就不折。

## X8 · 模板腔

给每一节都套上同一组小标题，凑出「结构感」，实际是把噪音乘以节数。

```markdown
<!-- 错：三节都是这套壳，其中两节的「注意事项」是硬凑的 -->
### 功能 A
**是什么**：……
**为什么**：……
**怎么做**：……
**注意事项**：无

<!-- 对：有什么写什么 -->
### 功能 A
一句话说清是什么。

怎么用：
1. ……
```

`doc-types.md` 里的骨架是**可选骨架**，不是必填表单。某节没有的内容就不写，不要写「无」。

## 自检清单

改完之后过一遍。任何一条为「是」都要回退：

- [ ] 出现了原文没有的 emoji？
- [ ] 有小节短于两行，且和相邻小节其实是一个连续动作？
- [ ] 有列表项单独读不懂？
- [ ] 有任何一条约束、例外、单位、版本号消失了？
- [ ] 加粗超过一眼扫过去能数清的数量？
- [ ] 有表格单元格塞进了完整的因果句？
- [ ] 主路径上的必要步骤被折叠了？
- [ ] 出现了内容为「无」「暂无」「不适用」的小节？
