# 中文文档专项

英文那套按 word 数的阈值直接套到中文上会误伤。这里定义中文的度量方式与专属规则。

## 语言判定

```text
CJK 字符占比 = CJK 字符数 / (CJK 字符数 + 拉丁词数)
占比 > 30% → 中文文档，用本文件阈值
```

代码块、行内代码、URL、YAML frontmatter 一律排除在统计之外。

## 度量对照

| 项 | 英文 | 中文 |
|---|---|---|
| 段落上限 | 80 词 | 160 字 |
| 章节上限 | 200 词 | 400 字 |
| 均句长 | 20 词 | 45 字 |
| 单句上限 | 30 词 | 70 字 |
| TL;DR 上限 | 5 条 | 5 条 / 120 字 |

中文句子切分边界：`。` `！` `？` `；` `…` 以及换行。**`，` 不是句子边界** —— 这正是「一逗到底」能藏进去的原因。

## C1 · 中英文之间加空格

```text
差： 用npm装好后运行3次
好： 用 npm 装好后运行 3 次
```

规则：CJK 字符与拉丁字母、阿拉伯数字相邻时插一个半角空格。

例外，不加空格：
- 全角标点两侧：`装好（约 2 分钟）` 而非 `装好 （约 2 分钟）`
- 行内代码与代码块内部，原样不动
- URL 内部
- 单位紧贴数字的既成写法：`3px`、`5GB` 内部不拆

## C2 · 标点全角统一

中文段落里用 `，。；：！？（）` ，不用 `, . ; : ! ? ( )`。

例外：
- 代码、命令、路径、版本号内的半角标点不动
- 中英混排的英文短语内部保留半角：`按 Ctrl+C, 然后回车` 里英文部分的逗号可保留，但整句的主标点用全角

## C3 · 破「一逗到底」

判据：单句 >45 字**且**逗号 ≥4。

```text
差（68 字，6 个逗号）：
这个功能默认是关闭的，如果你想打开它，需要先修改配置文件，然后重启服务，
注意重启会中断正在处理的请求，所以建议在低峰期操作。

好：
这个功能默认关闭。要打开它，先改配置文件再重启服务。
重启会中断正在处理的请求，建议在低峰期操作。
```

拆分优先级：
1. 先找**语义断点**（转折、因果、条件的边界），在断点处断句
2. 断句后如果剩下的是并列项，转列表（L2）
3. 每个新句只保留一个主谓结构

## C4 · 长定语前置改后置

中文长定语堆在名词前，读者要憋着一口气读到中心词才知道在说什么。

```text
差： 这是一个用于把 Markdown 文档中的内容和格式优化成适合注意力缺陷读者阅读的工具
     （中心词「工具」在第 38 字才出现）

好： 这是一个 Markdown 优化工具。它把内容和格式改造成注意力缺陷读者读得下去的样子。
     （第 8 字就知道是「工具」）
```

判据：「的」之前的修饰成分 >15 字。

改法：把中心词提前，修饰成分拆成后续独立句。

## C5 · 「的」连用

单句出现 3 个及以上「的」，通常意味着修饰层层套嵌。

```text
差： 这个用于处理用户提交的表单数据的验证的模块
好： 这个模块验证用户提交的表单数据
```

仅在 `deep` 档生效 —— 中文里「的」高频合法，误报率高，不适合当硬门禁。

## C7 · 虚词壳

这些词几乎总能删掉，删掉后句子更短、动作更明确。

| 虚词壳 | 改法 |
|---|---|
| 进行 X | 直接用 X 的动词：`进行优化` → `优化` |
| 实现 X | `实现数据同步` → `同步数据` |
| X 相关的 | 删：`缓存相关的配置` → `缓存配置` |
| X 方面 | 删：`性能方面有提升` → `性能有提升` |
| X 的问题 | 删：`兼容性的问题` → `不兼容` |
| X 工作 | 删：`测试工作` → `测试` |
| 对 X 做出 Y | `对配置做出修改` → `改配置` |

## C6 · 列表项句末标点

中文列表项句末**统一不加句号**，全文一致即可。多句的列表项内部用句号，末句仍不加。

```text
好：
- 缓存默认开启
- 性能瓶颈在序列化，不在网络
- Node 18 以下不兼容
```

## C8 · 不在句中软换行

中文没有空格分词，在句子中间硬插换行会破坏渲染、影响双击选词、也让 diff 变脏。

```text
差：
这个功能默认关闭，要打开它需要
先改配置文件再重启服务。

好：
这个功能默认关闭，要打开它需要先改配置文件再重启服务。
```

一句一行，长句就拆成多个短句，而不是折行。

## 中文文档的常见结构病

| 病 | 表现 | 对应规则 |
|---|---|---|
| 背景铺垫过长 | 前三段都在讲「随着业务发展」 | H1 —— 结论提到最前，背景折叠或删 |
| 标题全是名词短语 | 「概述」「设计」「实现」「总结」 | S4 —— 改成结论式 |
| 通篇无列表 | 并列项全塞在一段里用顿号连 | L2 |
| 结论在最后一段 | 「综上所述」才给答案 | S5 —— 整块搬到开头 |
| 客套收尾 | 「以上就是本文的全部内容，希望对你有帮助」 | 直接删，属于噪音 |
