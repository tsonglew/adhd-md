# 规则库

adhd-md 的全部规则。运行时按 `scope` 与 `level` 过滤本表，得到本次生效的规则子集。

## 怎么读这张表

| 列 | 含义 |
|---|---|
| **轴·档** | 形如 `F·2`。轴：`F` = 格式（正文词序列逐字不变，只动标记/空白/块顺序），`C` = 内容（改措辞，会产生新句子）。档：起效的最低 level，`1` = light 起、`2` = standard 起、`3` = 仅 deep |
| **自动化** | `det` = 脚本确定性修复，无需模型 · `lint` = 脚本能检出、模型来改 · `judge` = 纯模型判断 |

`scope=format` 只跑 `F` 轴规则，`scope=content` 只跑 `C` 轴规则，`both` 全跑。

阈值中「词」指英文 word，「字」指 CJK 字符。语言由脚本自动检测，中英混排按 CJK 字符占比 >30% 判为中文文档。

## X 组 · 反模式（扣分项）

**这组不是「要做什么」，是「不许做什么」。** 优化过头比不优化更糟：原文是难读，过度优化后是难读且信息丢失。

| ID | 反模式 | 判据 | 后果 |
|---|---|---|---|
| X1 | emoji 汤 | 正文出现 emoji，或 emoji 数 > 章节数 | 扣分 |
| X2 | 碎片化 | 标题密于每 5 行 1 个，或纯正文章节平均 <40 字 / <25 词 | 扣分 |
| X3 | 要点糊 | 列表项被砍成失去主谓的碎词 | 扣分 |
| X4 | 删信息 | `verify` 不通过 | **硬失败，拒绝写回** |
| X5 | 过度加粗 | 加粗 >12% | 扣分 |
| X6 | 表格滥用 | 把叙述性内容硬塞进表格 | 扣分 |
| X7 | 折叠滥用 | 主路径内容被藏进 `<details>` | 扣分 |
| X8 | 模板腔 | 每节都套同一组空话小标题 | 扣分 |

## 需要判断的规则详解

脚本只能检出上表里 `lint` 与 `det` 的部分。下面几条是模型判断的重点，也是最容易做错的地方。

### S5 结论前置：搬移，不改写

原文最后一段才说出结论 → 把**那一段整块搬到开头**。这属于 `F` 轴，词一个不改，所以 `scope=format` 也能做。

搬移后必须扫一遍**悬空指代**：被搬走的块里如果有「这个方案」「上述配置」「它」，指向的对象已经不在前面了。修指代属于 `C` 轴 —— 所以 `scope=format` 且检出悬空指代时，**放弃这次搬移**，在报告里记一条「需 content 权限才能安全前置」。

### S4 标题写结论

| 话题式（差） | 结论式（好） |
|---|---|
| 安装 | 用 npm 一行装好 |
| 性能考量 | 大文件下有三倍差距 |
| 关于缓存 | 缓存默认开，改不动就看这节 |

判据：读者只看目录，能不能知道每节的**答案**，而不只是**议题**。

### L2 句子转列表：复用原词的边界

允许（`F` 轴）：
> 支持三种模式：只改格式、只改内容、两者都改。

→

> 支持三种模式：
> - 只改格式
> - 只改内容
> - 两者都改

冒号后的并列成分原样搬进列表项，只删了顿号。**这不算改内容。**

不允许（越界成 `C` 轴）：给每个列表项补上解释、改写成完整句、调整用词。那要 `scope` 含 `content` 才可以。

### N4 折叠的判断标准

折叠进 `<details>` 的必须是**偏离主路径**的内容：故障排查分支、历史沿革、备选方案、完整参数表。

主路径内容一律不折叠 —— 折叠是给「不需要的人省视线」，不是给「作者省事」。判断法：读者要完成本文档的核心任务，需不需要展开它？需要就不折。

### X3 要点糊的识别

```markdown
<!-- 糊了：失去主谓，读者要自己补语义 -->
- 缓存
- 性能
- 兼容性问题

<!-- 好：每项自带完整判断 -->
- 缓存默认开启，改配置需重启
- 性能瓶颈在序列化，不在网络
- Node 18 以下不兼容
```

列表项不是关键词标签云。每一项应当能独立读懂。

### W4 回扫指令为什么要消灭

「如上所述」要求读者把眼睛移回去、重新定位、读完、再回来。对工作记忆是一次强制清空重载。ADHD 场景下这一次回跳经常直接导致放弃阅读。

改法：就地把那句话再说一遍。**重复不是冗余，重复是省掉一次回跳。**
